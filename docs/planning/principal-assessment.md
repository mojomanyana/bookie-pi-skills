## Product and actual state

Bookie is a portable operational knowledge ledger for people and agents. Git-tracked OKF Markdown and referenced Evidence bytes own the knowledge; Pi supplies explicit capture workflows and Redis supplies replaceable retrieval. Success means reconstructable project context, attributable decisions/evidence, useful degraded reads and rebuildable cited search—not another transcript archive or autonomous memory service. See the [vision](../product/vision.md).

More infrastructure would not fix the demonstrated boundary failures. The cost is owning a carefully tested controller and packaging boundary; revisit Redis only at ADR-0002's quality/cost/scale triggers, not because integration remains unfinished.

Priority exception to ordinary backlog order: finish this bounded BK-017 repair, then **BK-026 → BK-027 → BK-028 → BK-029**, before further BK-017 feature wiring. All four safety items are implemented pending independent integration review/delivery, and remain Ready rather than Done. No future feature is thereby authorized or completed. Thereafter use independently testable integration seams:

1. Deployment-owned expected runtime identity, trusted authorized preflight provenance and independent builder recipe/canonical-output comparison. Requalify changed runtime/deployment bytes before relying on an artifact identity.
2. Real-Redis versioned absent-output claims, explicit fenced begin-building, one-time output attachment and both-phase cancellation/cleanup. No placeholder counts or legacy-ID aliases.
3. One controller owning capacity, durable attempts and worker lifetime; prove duplicate/disconnect/unknown-outcome/restart behavior before exposing rebuild routes.
4. Redis Search, cited/context leased reads, stored-output verification, evaluation and compare-and-set activation/rollback; then hardened startup/Compose and representative scale qualification.
5. Local overlay and observable outage fallback (BK-020), followed by deterministic embedding contract/provider (BK-018). Vendor adapters wait for BK-019's dependencies and OQ-006; destination work retains its real-demand trigger.

## Tighten/refactor/revisit—not a rewrite

- **Fix behavioral oracles first.** Keep real-loader, actual transformed-output, object-corruption and owned-process regressions. Test counts and manifest string checks cannot substitute for these boundaries. Separate test quality from integrated product approval.
- **Keep useful boundaries.** Core versus Pi, auth versus Redis, deterministic codecs versus trusted orchestration, and process isolation versus cancellation ownership isolate real policy/nondeterminism. A single current implementation does not make them redundant.
- **Split by responsibility when touched, not by line count.** Git plumbing/base policy and mutation modules are large. Extract only an observed independently testable responsibility with unchanged error/bounds contracts; avoid a generic repository/provider layer or a second policy implementation.
- **Reduce documentation drift.** Specifications state accepted behavior, backlog orders work, and evidence records dated observations. Avoid treating handoff prose or previous approvals/digests as present qualification. SPEC-003 remains In progress; its earlier toolchain “implemented” summary was too broad.
- **Measure before performance rewrites.** Historical 50,000-file filesystem probes took tens of seconds; those are degraded full scans, not measurements of Redis's sub-500ms warm target. After safety repairs, profile traversal/parsing/output and representative admission/build coexistence. Do not add an authoritative cache, weaken validation or claim a speedup without candidate-matched measurements.
