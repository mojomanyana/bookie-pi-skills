# BK-012 completion evidence

## Scope

Delivered the release-0.1 read/query-only `@bookie/cli` package and the policy-bearing core write seams accepted by ADR-0007 and ADR-0008. The CLI exposes deterministic vault validation, bounded local search, and exact inspection. Every filesystem-writing CLI command, including initialization, create/amend, Evidence capture, and file-targeted export, remains deferred because portable Node cannot meet the accepted no-replace and same-user path-race guarantees.

## Files and behavior

- `packages/cli/src/cli.ts` implements strict ordered parsing for `bookie validate`, `bookie search`, and `bookie inspect`, static invocation failures, deterministic JSON/text output, signal cancellation, truncation notices, and inert terminal text.
- `packages/cli/package.json`, `packages/cli/tsconfig.json`, and root project references package the executable and force clean core/CLI builds before packing.
- `packages/core/src/concept-mutation.ts` and `packages/core/src/evidence-capture.ts` expose policy-bearing create, amend, and Evidence capture APIs while retaining policy-neutral low-level APIs.
- `packages/core/src/vault-secret-detection.ts` provides deterministic fail-closed request, retained-source, and streamed-resource credential detection with static redacted `WRITE-SECRET` failures.
- `packages/core/src/vault-validator.ts` reports an untruncated `immutablePolicyViolation` classification so CLI exit code 3 survives diagnostic truncation.
- ADR-0007 records fail-closed write-secret policy. ADR-0008 records the read/query-only release CLI and supersedes the broader CLI-surface expectation without weakening canonical publication guarantees.
- CLI and core tests cover command grammar, every search filter, exact inspect bytes, excluded-data omission, immutable exits beyond the diagnostic cap, terminal controls, cancellation, packaging, forbidden write imports, filesystem/Git immutability, blocked network clients, secret precedence, hostile inputs, scanner boundaries, and redacted excluded success.

## Acceptance demonstrated

- Clean package artifacts install and expose a working `bookie` binary.
- Validate, search, and inspect produce deterministic bounded results against explicit vault roots without network access or filesystem/Git mutation.
- Exact metadata filters, Unicode, dash-prefixed queries through an explicit separator, malformed grammar, static exit codes, and signal cancellation have process-level coverage.
- Excluded identities/content do not enter search output; untrusted terminal controls are escaped; every truncation mode is disclosed.
- Activity/Evidence immutability returns exit 3 even when ordinary diagnostics exceed their cap.
- Deferred filesystem-writing command names cannot reach core write or export APIs.
- Policy-bearing core writes reject possible credentials before publication with one static redacted failure, including retained concept bytes and incrementally streamed Evidence resources.

## Assumptions and follow-ups

- Release 0.1 intentionally has no filesystem-writing CLI command and no file-targeted export. Reintroducing one requires an accepted portable publication mechanism or explicit native support matrix.
- The low-level policy-neutral APIs remain available for trusted internal composition; user-facing CLI/Pi writes must use policy-bearing APIs.
- BK-013 is now Ready and may package the Pi extension's read, local-search, and validation tools. BK-014 remains blocked on BK-013 and the deferred write surface.
- “Remove mutation tests” remains ambiguous between mutation-testing tooling and the behavior suite in `packages/core/test/concept-mutation.test.mjs`; no validated behavior coverage was removed without clarification.

## Drift found and resolved

- Portable Node cannot simultaneously provide atomic no-replace directory publication, complete vault visibility, cross-platform operation, and protection from same-user destination swaps. ADR-0008 resolves the contradiction by deferring every filesystem-writing CLI command rather than weakening the accepted guarantees.
- The initial file-targeted JSONL design had a temporary-path replacement race. It was removed from release scope and retained only as a storage-neutral core sink API.
- No canonical/derived storage, append-only, sensitivity, provider, degraded-read, or no-auto-commit invariant was weakened.
