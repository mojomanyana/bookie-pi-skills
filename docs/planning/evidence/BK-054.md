# BK-054: Explicit correction of non-decision choice rows

Owner-authorized batch, 2026-11-19. Specification: SPEC-003 / ADR-0023.

Budget Split screenshots and the supplied diagnostic identify two actual choices
plus an aggregate progress-note row. Current extraction promotes bounded Unresolved
work text without a semantic classifier. This does not establish which original
tool argument authored that remote note.

The accepted fix is explicit, revision-bound reclassification through the trusted
dashboard, plus guidance against saving existing questions again in a progress
checkpoint. Source and answer history remain intact. No text heuristic is added.

The user approved the batch's six local regression groups before execution.
The isolated branch is `codex/choice-quality-20261119`, based on `286694b`.
Core and extension package versions are unchanged; the extension retains its exact
`pi-bookie-core` 0.3.0 dependency. Merge and publication remain pending.

## Implemented behavior

- Optional host-only `reclassify` controls publish an append-only classification
  bound to the original note and revision. They never write a decision answer.
- Exact read/search returns separate `choiceDisposition` metadata. Verified
  classifications remove only their selected rows; original note bytes remain.
- Same-process and independent-process writers share the existing core vault lock
  for the final answer/classification checks. Changed sources, access loss before
  publication and competing answers refuse; loss after publication is unconfirmed.
- A valid answer written by an older writer after classification remains readable
  with explicit conflict metadata. No automatic repair or silent winner is chosen.
- Guidance saves each genuine decision once and references existing questions in
  summaries. No language heuristic hides legacy, compound or multilingual choices.
