# BK-006 completion evidence

## Scope

Resolved OQ-002 and implemented the first SPEC-002 vertical slice: bounded, lossless byte loading of one Markdown concept, strict YAML 1.2 frontmatter parsing, byte-identical no-op serialization, and stable structured diagnostics. Schema and whole-vault validation remain BK-007; filesystem mutation remains BK-008.

## Public behavior

`loadConcept(bytes, { file, maxBytes?, maxDepth? })`:

- checks the byte limit before copying or decoding;
- decodes UTF-8 fatally and requires an exact byte-zero/opening and unindented closing frontmatter envelope;
- parses a single strict YAML 1.2 string-keyed mapping;
- rejects duplicate/non-string keys, non-mapping roots, aliases, custom tags, non-1.2 directives, unsafe integers/integral floats, non-finite numbers, excessive depth, and parser resource exhaustion;
- freezes the decoded plain frontmatter recursively;
- retains copied original bytes, envelope offsets, and the parsed Document only in private WeakMap state;
- returns bounded, content-free diagnostics with stable code, severity, file label, remediation, and UTF-8 byte/Unicode-column ranges where possible.

`serializeConcept()` accepts only the loader-owned object identity and returns a fresh copy of the original bytes. It rejects forged/spread objects rather than claiming lossless provenance.

Stable BK-006 codes are `CONCEPT-SIZE`, `CONCEPT-UTF8`, `FRONTMATTER-OPEN`, `FRONTMATTER-CLOSE`, `YAML-SYNTAX`, `YAML-UNSUPPORTED`, and `YAML-ROOT`.

## Acceptance demonstrated

- All golden concepts serialize byte-for-byte, including CRLF and absent final newline.
- Unknown frontmatter fields, comments, key order, quotes, flow style source, block-scalar style/values, Unicode, Markdown body, and delimiter-like body text remain available unchanged.
- Malformed YAML, duplicate/non-string keys, bad envelopes, invalid UTF-8, non-map roots, unsupported features, precision loss, and configured limit boundaries return stable diagnostics rather than content exceptions.
- Diagnostic messages are static, bounded, single-line, and do not echo a secret marker; parser ranges cannot escape frontmatter and use UTF-8 byte offsets.
- Input bytes are copied, decoded values and concepts are frozen, private YAML AST types do not appear in either transitive public declaration file, and forged concepts cannot use lossless serialization.
- ADR selection evidence and hostile-input performance are executable and rerun through the root quality command.

## Assumptions and follow-ups

- The 1 MiB and depth-64 defaults are operational core bounds accepted in SPEC-002; callers may only lower them through this API.
- Synchronous parsing cannot be interrupted in place. Bulk CLI/service callers must add worker or process deadlines in their later slices; the core regression budget detects parser-version degradation meanwhile.
- BK-007 must apply schemas and all SPEC-001 cross-file policy without changing these format diagnostics.
- BK-008 will use the retained private Document/envelope state for AST mutation and atomic conflict-safe writes.
- The initial 50,000-concept scale target belongs to whole-vault iteration/indexing and is not claimed by this one-concept loader slice.

## Drift found and resolved

- SPEC-002 delivery prose originally ordered inspect/search before safe mutation while the accepted backlog ordered BK-008/BK-009 first; the specification now matches backlog dependency order.
- SPEC-002's header omitted ADR-0005 after its dependency list cited it; both now agree.
- README and SPEC-001 still described OQ-002 as unresolved after the ADR; current status text now points to the accepted decision while historical completion evidence remains historical.
- A core golden Markdown link was initially vault-absolute without a fixture vault root; it is now a resolvable relative fixture link.
- Parser-native range and error behavior was not safe to expose directly; stable Bookie mapping now clamps and sanitizes it.
- No product requirement or prior accepted ADR was weakened or superseded.
