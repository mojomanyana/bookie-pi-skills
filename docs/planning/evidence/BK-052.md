# BK-052: Re-attach memory after a folder moves

The owner decided on 2026-11-17: "Explicit command, you confirm. A Bookie command shows the earlier project it believes this is (matching Git history), with old and new paths, and re-attaches only after you confirm in the terminal. Never automatic and never offered to the model." [ADR-0022](../../architecture/decisions/0022-reattach-moved-project-memory.md) records the design; REQ-035 states the requirement.

## Local verification

Base: `a6c35e7` (pi-bookie 0.7.0, core 0.3.0). Branch: `claude/reattach-moved-project-20261117`. Local checks only; no review, CI, merge or release has happened.

- `packages/pi-extension/test/reattach.test.mjs` has 14 tests using temporary directories and real Git repositories. Against the unmodified base build, all 13 tests of the first version failed: the location record, survey and command did not exist (missing `workspace.json`, missing survey function, `bookie-reattach` not registered).
- A single-line mutation check of the new logic applied 16 mutations. The first run left three survivors (trust check order, seed Project title, record key binding) and one mis-specified pattern; the tests were strengthened and all 16 mutations were then detected.
- Full `npm run check` with Node 24.22.3: format and lint passed; repository 464/464, service 323/323, CLI 48/48, core 310/311 and extension 175/176 (base: the same except extension 161/162). The two failures are identical on the untouched base and specific to the sandbox: core's chmod-0o500 staging test running as root, and the extension's nested `npm install` failing to complete.

## Limits

No Pi host, model, provider or JEV run was made; the command was exercised with fake Pi hosts that register real Bookie hooks. A real cross-volume move was simulated by copy and delete. Memories last opened before location records existed cannot be matched (OQ-016).
