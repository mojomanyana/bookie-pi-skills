# BK-007 completion evidence

## Scope

Implemented the SPEC-002 production validator for one explicit filesystem vault. It consumes the BK-006 lossless loader and canonical SPEC-001 schemas, then validates manifest policy, Bookie/generic OKF records, local CommonMark links, current-tree relations and Decision lifecycle, Evidence resource containment, and exact-byte digests.

Git-base Decision retention, Activity/Evidence immutability, pinned target identity, Git tracking/submodules, and base resource changes remain BK-009.

## Files and behavior

- `packages/core/src/vault-validator.ts` orchestrates the public asynchronous `validateVault(root, options?)` API.
- Package-private modules isolate strict YAML decoding, cancellation, deterministic diagnostics, filesystem snapshots/bounds, CommonMark parsing, internal models, and current-tree policy:
  - `strict-yaml.ts`
  - `vault-cancellation.ts`
  - `vault-diagnostics.ts`
  - `vault-filesystem.ts`
  - `vault-markdown.ts`
  - `vault-model.ts`
  - `vault-policy.ts`
- `packages/core/scripts/copy-schemas.mjs` copies canonical root schemas into `dist/schemas` during build; `packages/core/package.json` includes runtime assets and explicit Ajv, formats, CommonMark, and YAML dependencies.
- `packages/core/test/vault-validator.test.mjs` and `vault-validator-review-regressions.test.mjs` exercise examples, full vault fixtures, materialized policy fixtures, direct manifest consumption, required OKF bundle metadata, independent multi-error reporting, security races, package relocation from clean source, cancellation, limits, generic OKF, exact binary/CRLF hashing, and hierarchical redaction.
- SPEC-002, security architecture, toolchain, documentation index, and core README define the accepted public and failure contracts.

## Public contract

`validateVault()` returns:

- `valid`: true only when validation is complete and has no errors;
- `complete`: false when bounds, unreadable/torn required input, invalid/missing manifest policy, or diagnostic truncation prevents a complete claim;
- `diagnosticsTruncated`: specifically identifies diagnostic-cap exhaustion;
- deterministic static diagnostics and the resolved real root.

Cancellation consistently rejects with `AbortError`, including custom abort reasons, timeout signals, root-resolution failure, policy evaluation, and late final-snapshot verification. Invalid programmer limits reject with `TypeError`; vault content failures return diagnostics. The validator consumes exactly one complete direct manifest document and requires an OKF 0.2 root `index.md`.

Default limits are 64 KiB manifest, 1 MiB per Markdown file, YAML depth 64, 100,000 traversed entries, 50,000 concepts, 512 MiB aggregate Markdown bytes, 2 GiB streamed Evidence bytes, and 1,000 diagnostics. Callers may lower but not raise them through this API.

## Red evidence

The first focused test run failed before implementation because the validator API did not exist:

```text
SyntaxError: The requested module '../dist/index.js' does not provide an export named 'DEFAULT_MAX_VAULT_CONCEPTS'
ℹ tests 13
ℹ pass 12
ℹ fail 1
```

Subsequent failing regressions demonstrated and then fixed:

- duplicate CommonMark definitions were traversed backwards instead of using the first definition;
- invalid UTF-8 in reserved Markdown threw through the content API;
- an ancestor-directory symlink race allowed an outside concept to be parsed;
- in-place manifest changes after reading could still yield `valid: true`;
- Evidence metadata/content changes during streaming were not detected with high-resolution change time;
- schema-invalid Bookie records skipped `TYPE-ALLOWED` and `UID-UNIQUE` checks on otherwise trustworthy fields;
- an invalid manifest disabled fail-closed sensitivity redaction;
- an excluded Evidence resource symlink leaked its resource path through `VAULT-IO`;
- predecessor-only Decision links omitted `DECISION-SUPERSESSION`;
- manifest/concept size limits did not mark validation incomplete;
- cancellation propagated custom reasons or `TimeoutError` and was not checked during final snapshot verification;
- direct AST schema lookup depended on repository layout and failed after package relocation;
- direct Evidence reads buffered whole resources rather than streaming.

The independent PR review then supplied additional red reproductions. Remediation added tests before code for each behavior:

- direct manifest wrapping ignored a trailing YAML document and rejected a legal document-start marker;
- decimal scalar text could round into a schema-valid safe integer;
- missing or plain `index.md` was accepted as an OKF bundle;
- schema-valid deeply segmented exclusion globs exhausted the JavaScript call stack, and excluded entries did not debit traversal bounds;
- excluded OKF source-resource, project, support, resource, relation, traversal-normalized, and body-link ancestor paths leaked through `VAULT-IO`;
- unreadable or torn Evidence returned `complete: true`, and failed streamed bytes did not debit the aggregate bound;
- cached UID errors and unrelated schema errors suppressed independent policy diagnostics;
- inverse-relation scans were quadratic, duplicate inverse cardinality was filtered incorrectly, and policy evaluation did not yield for timer cancellation;
- root-resolution cancellation could resolve normally;
- multiply linked Evidence and unconsumed linked vault files could alias an outside inode;
- clean `npm pack` omitted `dist`, package engines were absent, and loader ownership was only structural in TypeScript;
- exact-byte digest, active/exact bound, deferred phase, cycle/self-supersession, one-segment/recursive glob, and CommonMark boundaries lacked production regressions;
- deeply nested CommonMark block containers could monopolize synchronous parsing within the byte limit; suspicious container input is now isolated behind a cancellable five-second worker and checked for actual AST depth;
- intentional CRLF fixtures made a meaningful range-based `git diff --check` fail.

## Acceptance demonstrated

- Both complete valid vaults pass production validation.
- All five valid policy proposed trees pass.
- All 21 invalid current-tree policy cases emit their declared profile codes; the mixed base/current resource-byte case emits current-tree `EVIDENCE-DIGEST` without claiming a BK-009 immutability result.
- One run reports independent `CONCEPT-SCHEMA`, `MARKDOWN-LINK`, `RELATION-TARGET`, `EVIDENCE-RESOURCE`, and `EVIDENCE-DIGEST` findings.
- Schema-invalid Bookie candidates still enforce trusted path/type/UID policy while only schema-valid records may satisfy project/relation/support targets.
- Generic OKF concepts—including generic `Task`—remain outside Bookie policy unless they carry a `bookie` mapping.
- Inline links, images, used references, Unicode escapes, external schemes, fragments, duplicate definitions, traversal, encoded separators, fenced-code controls, actual block-container depth, worker deadline, and worker cancellation cover the documented CommonMark boundary without rendering or fetching.
- Evidence hashing is incremental and exact; configured-root, real-root, size, symlink, hardlink, metadata-race, aggregate-byte, missing, binary/CRLF, and digest cases fail closed. Bytes streamed before a failed hash still consume aggregate allowance.
- Every enumerated/read/hashed path retains deduplicated ancestor and file identities through final validation. Device, inode, link count, mode, size, nanosecond modify/change times, and realpath are rechecked.
- Excluded record paths, UIDs, titles, bodies, relation targets, local link targets, Evidence resource paths and their diagnostic ancestors, and outside marker content do not appear in diagnostics.
- Diagnostic order and truncation are deterministic; incomplete and truncated states cannot appear valid.
- A real tarball built from a clean source copy installs in a relocated consumer, imports successfully, carries byte-identical canonical schemas, exposes no parser-specific public declarations, declares Node 24 support, and validates the complete fixture with its declared runtime dependencies.

## Assumptions and follow-ups

- `policy.exclude` is an anchored segment-glob omission boundary; invalid manifests cannot authorize exclusions, though parseable excluded sensitivity classes are still used for fail-closed diagnostic redaction.
- `npm run benchmark:vault --workspace @bookie/core -- 50000` reproducibly completed an integrated 50,000-file generic-concept vault as valid and complete under the default limits in 79.6 seconds at 243 MiB RSS on the local Node 26 Linux/WSL2 environment. Validation has no product latency SLO. The final `npm run check` also passed on the pinned Node 24.19.0 release baseline with 461 repository and 106 core tests.
- Node lacks a portable `openat` directory-handle API. The validator compensates with required no-follow final opens, single-link regular files, and retained ancestor/file identity and nanosecond timestamp snapshots before, after, and at final completion; unsupported platforms and detected races fail closed, with unreadable/torn input returning `complete: false`.
- The generated schema copy is disposable package output; root `schemas/` remains authoritative.
- BK-008 must apply the same containment discipline inside atomic conflict-safe mutation windows.
- BK-009 must consume the 11 deferred base-sensitive policy cases without weakening current-tree results.

## Drift found and resolved

- Initial SPEC-002 wording would have reserved profile type names such as `Task`, contradicting SPEC-001 and ADR-0001; Bookie detection now requires a `bookie` mapping.
- Ordinary Markdown link behavior was underspecified; source files, link node forms, local/external resolution, percent encoding, fragments, queries, directories, and raw HTML are now explicit.
- `truncated` originally conflated diagnostic truncation and incomplete filesystem/resource validation; `complete` and `diagnosticsTruncated` now have separate meanings.
- The test-only fixture validator returned early after manifest failure and followed directory symlinks; production validation continues independent safe checks without reusing that oracle.
- The root schema layout was not relocatable as a core runtime dependency; build-time canonical asset copying plus a clean-source package relocation smoke test resolves it without creating another tracked schema authority.
- Historical concept-schema lookup was underspecified. Profile 1.0's current common/type files are now explicitly frozen, and another profile generation requires an ADR-backed version-addressed registry before changing that authority.
- No accepted ADR or product requirement was weakened or superseded.
