# BK-053: Safe native save-validation feedback

Status: implemented and locally verified on 2026-11-19. Merge and publication remain pending; no release is claimed.

## Reported failure

The user supplied a read-only diagnostic of the original Repair Desk Pi session on 2026-11-19. Its native log recorded three direct `bookie_remember` calls on 2026-11-18 with summary lengths 3,150, 2,632 and 2,245 characters. Each had `isError: true` and the native error `summary: expected at most 2000 characters`, followed by a private "Received arguments" dump. No call used codemode and none returned a save locator. Pi's native input validation rejected the calls before Bookie executed; the history shown to the agent instead contained Bookie's generic reference-only notice.

The installed package metadata reported pi-bookie 0.8.1; the session loader did not explicitly record the loaded extension version. The full private log and submitted contents are not copied here. This is user-supplied execution evidence, not a fresh local reproduction.

The user subsequently reported a corrected 1,674-character summary and 134-character next action saved and read back successfully. This establishes a bounded-input workaround for that run, not verification of the proposed repair.

## Accepted scope

The owner authorized the focused fix and three local regression groups on 2026-11-19:

1. Native input rejection remains actionable, including the 2,000-character summary limit, while private argument dumps remain hidden.
2. Corrected input saves once, returns an exact receipt, and can be read back.
3. The checkpoint survives a fresh session while existing answers and unanswered choices remain unchanged; affected existing suites pass.

Use isolated local fixtures and existing suites only. No model, judge, JEV, public-research or live-SSH calls, active-installation changes or publication are authorized by these checks. Preserve current save limits, failure status, disclosure and capture checks, canonical records, exact core 0.3.0 compatibility, and recall-before-retry for uncertain saves.

## Implementation

The context filter recognizes only an error result for the exact `bookie_remember` tool with Pi's exact native validation header. It replaces the entire diagnostic with fixed guidance that states the existing field bounds, including the 2,000-character summary limit. It never copies caller-controlled diagnostic paths, argument values or the native "Received arguments" dump, and removes result details. The error flag and call identity remain intact; no successful receipt or mutation claim is invented. Bookie's own fixed pre-write input error is centralized and retained as public failure status. Both remain intelligible after context reset or another result losing authority. All successful-result authority checks remain unchanged.
