# BK-016 completion evidence

## Scope

Defined and accepted the release 0.2 retrieval-service protocol, authentication and authorization model, Redis projection/build state machine, and one-host Docker threat model for SPEC-004. ADR-0010 resolves OQ-003 and OQ-004 and establishes the implementation boundary for BK-017.

## Files and behavior

- `docs/architecture/decisions/0010-service-protocol-auth-and-projection.md` selects Fastify and standalone random opaque bearer tokens with digest-only verifiers, expiration/revocation, constant-time verification, separate admin credentials, and server-side per-vault scopes.
- ADR-0010 defines approved-commit validation, sensitivity and secret boundaries, deterministic build identity, vault-scoped Redis keys, one controller job per build attempt, fenced candidate writes, crash recovery, reader leases, compare-and-set activation, rollback, cancellation, and garbage-collection safety.
- ADR-0010 also defines loopback-first service exposure, mandatory TLS for remote traffic, private Redis networking and ACLs, secret-file mounts, container hardening, bounded requests/work, safe logs/metrics, and initial concurrency/rate/deadline limits.
- `schemas/service/v1/protocol.schema.json` defines strict versioned health, index, search, context, rebuild, cancellation, activation, and static error payloads. It reuses canonical path, UID, and date definitions and bounds trust, freshness, sensitivity, lifecycle, and workflow filters.
- `docs/specs/004-retrieval-service.md` makes the protocol, configuration contract, authorization boundary, and implementation acceptance criteria normative.
- `test/service-design-contract.test.mjs` compiles every public schema definition and covers valid, error, unknown-field, identifier, date, filter, limit, and state-correlation boundaries.

## Acceptance demonstrated

- A strict version 1 schema exists for every accepted route and static error shape.
- The authorization matrix binds reader and admin scopes to server-configured vault grants before Git, job, build, context, or Redis lookup.
- Random opaque bearer-token storage, verification, expiry, revocation, replay residual risk, TLS boundary, and safe logging are explicit.
- Redis keys and indexes are subordinate to opaque vault namespaces; incomplete, cancelled, interrupted, stale-policy, or foreign-vault builds cannot activate.
- Controller-job fencing, startup owner epochs, request leases, compare-and-set activation, self-activation rejection, and rollback preserve one complete serving generation across concurrency, cancellation, crash, and cleanup races.
- Excluded or detected-secret content and identifiers cannot enter projections, embeddings, jobs, logs, metrics, or errors.
- The Compose threat design requires no Redis host port, read-only vaults, secret mounts, non-root/read-only containers, dropped capabilities, health checks, and bounded resources.

## Drift found and resolved

- Initial service-specific path, UID, and freshness grammars diverged from canonical profile definitions; the protocol now references the canonical schema.
- Initial activation/cancellation and reader/garbage-collection descriptions left races; ADR-0010 now specifies atomic shared transitions, leases, and fencing.
- Initial approved-ref epoch handling prevented legitimate rollback; activation now re-evaluates current reachability and policy without making the ref tip immutable build identity.
- Initial job retry/restart semantics could wedge or contaminate candidates; one controller, one non-terminal vault job, owner epochs, and every-write fencing now close that gap.
- Initial protocol omitted trust and freshness filters required by SPEC-004; both are now strict bounded inputs.
- No canonical, sensitivity, authorization, provider-generation, degraded-read, or Redis-derived-only boundary was weakened.
