# BK-008 completion evidence

## Scope

Implemented the SPEC-002 safe mutation boundary for one explicit filesystem vault. Core now creates complete schema-valid Bookie concepts and amends retained YAML Documents through typed set/remove edits with exact source-hash conflicts, full-window coordination, bounded validation, and same-directory atomic publication.

Evidence capture, Git-base immutability, CLI commands, and Pi tools remain later backlog items.

## Files and behavior

- `packages/core/src/concept-mutation.ts` orchestrates public `createConcept()`, `amendConcept()`, and `computeConceptSourceHash()` behavior.
- Package-private mutation modules isolate request cloning/bounds, public result and diagnostic models, schema/manifest/collision validation, and filesystem coordination/publication.
- `packages/core/src/concept-loader.ts` retains the private YAML Document used for amendments while preserving exact original bytes for no-op and body-only changes.
- `packages/core/src/vault-manifest.ts` shares canonical schema and manifest loading with `validateVault()` without adding another schema authority.
- `packages/core/test/concept-mutation.test.mjs` covers all profile types, exact hashes, lossless amendments, path and identity rejection, UID collisions, concurrency, cancellation, bounds, temporary cleanup, and adversarial filesystem races.
- SPEC-002 and the core README document the public request/result, coordinator, conflict, path, preservation, and failure contracts.

## Public and failure contract

- Create accepts a complete profile 1.0 frontmatter mapping and exact body text, validates type/UID/manifest policy, scans the bounded vault for UID collisions, and publishes only to an absent safe target.
- Amend requires the exact `sha256:` token over previously read bytes, preserves stable type/profile/UID identity, interprets all edit paths against the original document, and checks source bytes and inode identity again immediately before publication.
- Body-only amendments preserve frontmatter and delimiter bytes exactly. Semantic no-ops preserve the original inode and all bytes.
- Mutation paths reject traversal, host paths, encoding, controls, reserved concept names, every case variant of `.git`, manifest exclusions, unsafe ancestors, more than 64 segments, more than 255 UTF-8 bytes per segment, or more than 4,096 UTF-8 bytes total before coordination.
- Writes use an exclusively created same-directory temporary regular file, flush and close it, recheck root/parent/target/temp identities, and rename atomically. Cancellation before publication cleans up or reports observable I/O failure; cancellation cannot report an ambiguous failure after rename begins.
- Core serializes its own mutations per real vault root. Pi must later adapt the complete window to `withFileMutationQueue()` through the documented `runExclusive` contract.
- Expected content, path, target, conflict, bounds, and I/O failures return static structured diagnostics; invalid programmer limits throw `TypeError`, and cancellation rejects with `AbortError`.

## Red evidence

The first focused mutation test failed because the public mutation exports did not yet exist. Test-first implementation then exercised success and required error/boundary paths.

Review regressions were also observed failing before remediation:

- a body-only amendment changed serializer-sensitive untouched frontmatter bytes;
- `.git` targets reached publication, oversized paths reached the coordinator, and excessive segments could throw `RangeError` instead of returning `MUTATION-PATH`;
- aggregate edit-path bytes produced late `CONCEPT-SIZE` rather than bounded candidate preparation;
- removing original sequence indexes `0` and `1` in caller order could retain the wrong element.

Each regression passed after the focused fix. Additional disposable probes verified all permutations of sibling and nested mixed sequence edits, same-byte inode replacement, late target hardlink creation, exact/+1 UTF-8 path limits, and 64/65 segment boundaries.

## Acceptance demonstrated

- Traversal, encoded/absolute paths, `.git`, exclusions, unsafe parents, symlink targets, and multiply linked targets fail without touching outside bytes.
- Concurrent amendments from one source token produce one success and one observable conflict; late source changes or deletion never lose the external update.
- Concurrent creates with one UID at different paths publish exactly one concept; the other returns `UID-UNIQUE`.
- Temporary staging is same-directory, exclusive, bounded, flushed, identity-checked, cleaned when safe, and never exposes a partial canonical target.
- Unknown fields, comments, key order, scalar styles, CRLF envelopes, file mode, untouched bodies, body-only frontmatter bytes, and no-op source bytes are covered.
- All eight initial profile types amend and leave a valid current vault.
- Result hashes match exact published bytes, and changed paths contain only the canonical target when bytes changed.
- Mutation runtime code invokes no Git command, network service, Pi API, or process exit.

## Assumptions and follow-ups

- The coordinator guarantee applies to conforming callers that invoke and await the callback exactly once. Uncoordinated external processes remain outside the lock contract, but observed pre-publication changes fail closed.
- Related relation/inverse/support changes remain multi-file operations and require `validateVault()` before submission.
- [OQ-009](../open-questions.md#oq-009-pre-write-secret-detection-policy) now blocks CLI/Pi mutation exposure until deterministic local secret detection, override rules, and redacted failure behavior are accepted. BK-008 intentionally does not guess that policy in the low-level primitive.
- BK-009 is the next ordered implementation item and adds evidence capture plus Git-base immutability validation.

## Drift found and resolved

- The initial mutation contract lacked executable path/output ceilings and did not reserve Git metadata. SPEC-002 now pins portable segment, component, and total limits and rejects `.git` case variants.
- Body-only exact-frontmatter preservation and original-index sequence edit ordering were implicit in the lossless/order-independent contract; SPEC-002 and regression tests now make those behaviors explicit.
- Security architecture requires pre-write secret scanning but no accepted detector/override policy exists. OQ-009 records the unresolved decision and blocks write-facing CLI/Pi delivery rather than weakening or inventing policy inside BK-008.
- No accepted ADR or product requirement was weakened or superseded.
