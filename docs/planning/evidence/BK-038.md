# BK-038: portable task-continuity guidance

Status: implemented local instruction candidate; offline checks passed; not committed or published.
No release, provider evaluation or runtime behavior change is claimed.

The operator approved a combined ecosystem improvement after reviewing repeated
questions and recovery friction in a historical session. This slice uses the
existing structured Activity checkpoint and exact prepared-context contracts.
It adds a discoverable skill and recipe rather than a competing task store,
authority ledger, automatic hook or service.

Package manifests expose the same resource for root Git/local and npm
subpackage installation. The skill keeps scoped original user references,
untrusted summary semantics, evidence ownership, observable failures and a
session/already-authorized local fallback. A source hash is not approval, and
a withheld write result is not proof that retry is safe.

A focused actual-Pi discovery check failed before packaging changes because the
npm resource list omitted skills. The full required `npm run check` completed with exit 0: formatting, lint, build,
and 1248 tests passed; zero failed, skipped or cancelled. Workspace counts were
463 repository, 323 service, 48 CLI, 305 core and 109 Pi-extension tests.

The discovery assertion was narrowed after its full-suite phase to permit future
unrelated skills while requiring one bookie-continuity resource per package.
That final test passed separately, along with its formatting/lint and
`git diff --check`; no duplicate full run was needed. The final instruction
also explicitly forbids alternate-tool bypass of denied disclosure.

`npm pack --dry-run --ignore-scripts --json` found the skill and its relative
recipe among the 45 pi-bookie files. Nothing was packed for publication or
uploaded. Installed Pi documentation was read for package/skill conventions.
These are offline discovery and existing-contract regression checks, not a
measured fresh-subject UX or memory-quality evaluation.
