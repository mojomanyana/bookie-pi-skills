Decimal digits only; malformed/missing/duplicate/zero/above-limit/out-of-order options return static CLI-INVOCATION exit 2 before work. The setting supplies a usable caller deadline without an ambient bypass or unbounded timeout. It authorizes no deferred writer/export command.

A private supervised process runs the same three read-only core operations. The parent retains invocation parsing, signal/deadline ownership and all output formatting (including exact inspect bytes and search filter order). It buffers the result until worker/owned-descendant teardown is confirmed. Startup, crash, protocol, deadline or teardown failure emits only static CLI-OPERATION exit 1 and no partial/success output; explicit cancellation emits CLI-CANCELLED exit 1 only after confirmed teardown. Core TypeError still maps to invocation exit 2. A separate one-second teardown allowance cannot convert uncertainty to success.

POSIX uses a detached owned group and group kill, not leader-only kill. Linux confirms live versus zombie descendants through bounded procfs reads; opaque/permission failures are not evidence of death. Windows uses fixed checked `taskkill /PID ... /T /F` plus worker close; non-Linux paths have not been qualified here. Core remains portable and untouched at its read API boundary. Source guards now cover every CLI source module, admitting only the private fixed worker launch, fixed OS teardown and read-only process-state inspection. Existing mutation/export/network prohibitions and process no-write/network controls remain.
