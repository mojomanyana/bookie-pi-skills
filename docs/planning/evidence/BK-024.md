# BK-024 completion evidence

## Scope

Updated the repository's single GitHub Actions workflow from the Node 20-based `actions/checkout@v4` and `actions/setup-node@v4` lines to their maintained Node 24-native v5 releases. The workflow still runs one clean install and the complete root quality command on the Node version pinned by `.nvmrc`, with read-only repository permissions and npm caching.

No application dependency, source behavior, canonical data, package API, runtime baseline, or deployment boundary changed.

## Files and behavior

- `.github/workflows/ci.yml` now uses `actions/checkout@v5` and `actions/setup-node@v5` exactly once while retaining `ubuntu-latest`, `node-version-file: .nvmrc`, `cache: npm`, `npm ci`, `npm run check`, the ten-minute job bound, and `contents: read`.
- `test/repository.test.mjs` prevents regression to a non-Node-24 action line. Its scanner covers both shorthand `- uses:` steps and named steps whose `uses:` field appears on a following line.
- `docs/planning/toolchain.md` records the CI action and runner boundary.

## Red evidence

The merged-main check immediately before BK-024 passed but emitted a GitHub annotation that `actions/checkout@v4` and `actions/setup-node@v4` targeted deprecated Node.js 20 and were being forced onto Node 24.

The first focused repository test then failed as intended:

```text
expected: actions/checkout@v5
actual:   actions/checkout@v4
1 failed, 0 passed
```

Review found one additional boundary before delivery: the initial scanner recognized only shorthand list steps, so a named step could hide another action version. A named-step control was added, the scanner was repaired, and the final review approved the exact candidate with no remaining finding.
