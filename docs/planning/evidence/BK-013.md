# BK-013 completion evidence

## Scope

Packaged the first SPEC-003 Pi extension slice with `bookie_read`, filesystem-only `bookie_search`, and `bookie_validate`. Each tool requires an explicit vault root and delegates canonical parsing, search, sensitivity, source attribution, and validation behavior to `@bookie/core`.

Write, checkpoint, service retrieval, and export tools remain later backlog work.

## Files and behavior

- `packages/pi-extension/src/index.ts` registers strict TypeBox tool inputs, uses Pi `StringEnum`, resolves explicit local vault paths, propagates cancellation, and throws on failed or incomplete operations.
- Tool output identifies filesystem mode, source state/hash, trust and freshness signals where available, labels retrieved text as untrusted, escapes terminal controls, and enforces Pi's 50KB/2,000-line limits with explicit truncation notices.
- Explicit reads of sensitivity-excluded concepts fail with one static redacted error before content or identifying metadata enters the persisted tool result.
- `packages/pi-extension/package.json`, the root Pi manifest, production build dependencies, and the narrowed root `prepare` script support local-path and clean Git-package installation without relying on omitted development dependencies.
- The extension starts no background resource and contains no network, mutation, commit, or push path.

## Acceptance demonstrated

- Local-path installation records the Pi package, and the production Git-install simulation builds and loads all three tools from a clean checkout.
- Read by path or UID, filtered local search, and validation run against temporary complete vaults through core.
- Retrieved results report filesystem-only mode, working-tree provenance, source hashes, and untrusted handling.
- Missing selectors, missing vaults, incomplete operations, cancellation, excluded reads, and output boundaries fail or truncate observably without error-looking success.
- Source inspection and runtime side-effect tests show no network, filesystem write, Git commit, or Git push capability in this slice.

## Assumptions and follow-ups

- Configuration discovery is intentionally absent: explicit per-call vault paths support vaults outside the code repository without reading untrusted project configuration.
- Service retrieval and fallback merging begin only after the service contract exists; current search is explicitly filesystem-only.
- BK-014 can become Ready after this evidence merges, but its required parallel mutation behavior intersects the still-ambiguous request to remove “mutation tests.” Clarification is required before changing that accepted acceptance coverage.

## Drift found and resolved

- A production Git install originally omitted the compiler used by `prepare`; build-only production dependencies and a narrowed prepare target now make installation reproducible.
- Returning explicitly read excluded content would persist it in Pi session history. The extension now fails closed with static redaction while leaving the lower-level core inspect contract unchanged.
- One-line JSON truncation could discard all useful content. Oversized reads now retain bounded metadata, a canonical source pointer, and an inert source prefix before disclosing truncation.
- No accepted canonical, sensitivity, provider, or degraded-read boundary was weakened.
