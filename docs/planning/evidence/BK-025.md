# BK-025: Behavior-preserving project simplification

Status: Ready; implemented and independently approved on the development branch, pending PR #28 merge/CI evidence at the 2026-10-10 UTC closeout. The refactor's original 822-case measurements below are historical; current integrated verification is appended below.

This refactor consolidates repeated validation, policy and service helpers, reduces test scaffolding, and simplifies the TypeScript build graph. It preserves the existing core, CLI, Pi and service contracts under ADR-0004. BK-017 controller integration and deployment qualification remain separate work.

## Baseline and acceptance

Acceptance requires unchanged public APIs, serialized output, errors and security boundaries; equivalent Unicode excerpts; retained distinct functional tests; successful package installation and quality checks; and independent review. The dependency versions and lockfile are unchanged by the refactor.

Baseline verification: Node `24.19.0`, npm `11.5.2`; `npm ci --no-audit --no-fund` followed by `npm run check` exited 0. All 830 tests passed, with none failed or skipped. Combined install/check elapsed time was 150.9 seconds in one local run, not a controlled performance benchmark. The lockfile was unchanged.

## Changes

- Core shares one positive-limit validator, one trusted-policy projection and one schema-diagnostic mapper. Export and vault validation share the same bounded-limit setup; the resource-free query policy remains separate. Public exports, constant values, errors and option evaluation order are unchanged.
- Search excerpts accumulate UTF-8 byte counts and join the chosen window once instead of repeatedly copying and measuring it. First-match and left-before-right selection semantics stay unchanged.
- Service codecs share one private own-data-field reader while keeping their individual static-error boundaries. One Ajv instance serves each HTTP service's request and response validators. Mount lookup makes one linear longest-match pass per lookup without sorting temporary arrays.
- One forced TypeScript project-reference graph replaces repeated core/consumer builds. Standalone workspace tests and forced packaging builds remain supported. CLI packaging tests use a separate source copy instead of deleting the live workspace's outputs.
- Schema tests reuse compiled validators. Repeated runtime fixture construction is shared. Spec-era test-only policy/fixture validators were removed because production validators exercise the same independent fixture expectations. The direct-YAML experiment and redundant source-presence test were retired; real mutation goldens now also assert literal/folded decoded values. Architectural import/side-effect guards remain.
- README and toolchain documentation distinguish delivered functionality from the unfinished service and describe the actual build flow.

These changes use the existing shared-domain and adapter boundaries. No new class hierarchy, provider framework, dependency or feature was introduced.

## Verification

Node `24.19.0`, npm `11.5.2`: a clean `npm ci --no-audit --no-fund` followed by `npm run check` exited **0**, with **822 passed / 0 failed / 0 skipped**: 461 repository, 75 service, 10 CLI, 255 core and 21 Pi cases. Formatting, lint, forced-graph typechecking, package relocation/install and Pi local/Git installation all passed. Dependency metadata and lockfile are unchanged.

The case count changed from 830 to 822: seven repeated invalid-vault subcases, two historical YAML-library cases and one duplicated source-presence case were removed; one public Unicode-window test with 14 literal scenarios and one mount-order/alias regression were added. Distinct functional and security cases remain.

Independent reviewers checked core behavior, test/build changes and service behavior, with no unresolved findings. Additional external comparisons covered 15,000 seeded Unicode cases, 10,000 further UTF-8/lone-surrogate cases, option/diagnostic/policy behavior, codec inputs, mount order/alias behavior and concurrent HTTP responses. Test-fixture consolidation independently matched 123 file/directory/link entries. All comparisons matched the baseline.

Review found and corrected a proposed incremental-build regression: removing `dist` while retaining `.tsbuildinfo` could falsely succeed without emitting JavaScript. The final root and all four workspace build commands restore deleted outputs and schemas. An injected TypeScript error stopped `npm test` before any runner started.

Removing these would change behavior. BK-017 production deployment and controller/search/activation work remains outstanding; offline checks do not establish those acceptance gates.
