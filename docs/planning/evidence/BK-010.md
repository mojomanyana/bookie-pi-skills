# BK-010 completion evidence

## Scope

Implemented the SPEC-002 bounded filesystem search and exact inspect boundary in `@bookie/core`. Core can now scan one explicit local vault without Git, Redis, Pi, a provider, or a network service; match schema-valid Bookie titles and Markdown bodies; apply exact metadata filters; and return bounded working-tree results with source, freshness, sensitivity, trust, truncation, and completeness signals.

Canonical JSONL export, CLI commands, Pi tools, shared retrieval, and local/shared result fusion remain later work.

## Files and behavior

- `packages/core/src/filesystem-query.ts` implements public `searchVault()` and `inspectConcept()` orchestration, request/selector validation, exact matching and filters, deterministic result selection, UTF-8-safe excerpts/source prefixes, hashes, and structured outcomes.
- `packages/core/src/filesystem-query-model.ts` defines provider-free public request, option, source, signal, hit, success, and failure types.
- `packages/core/src/vault-query-scan.ts` performs one bounded manifest-aware safe scan, validates Bookie candidates, distinguishes referenced Markdown Evidence resources, classifies sensitivity, redacts excluded diagnostics, tracks UID ambiguity, and rechecks filesystem identity before content can return.
- `packages/core/src/vault-filesystem.ts` now exposes unsafe-entry observation to query callers without changing canonical validation authority; search marks such scans incomplete and inspect returns no content.
- `packages/core/src/vault-diagnostics.ts` adds static `INSPECT-INPUT`, `INSPECT-NOT-FOUND`, and `INSPECT-AMBIGUOUS` failures.
- `packages/core/test/filesystem-query.test.mjs` covers success, errors, boundaries, exclusions, generic OKF, Evidence resources, cancellation, races, unsafe files, Unicode, ordering, declarations, and forbidden runtime dependencies.
- `packages/core/scripts/benchmark-filesystem-query.mjs` reproduces a 50,000-concept bounded scan.
- SPEC-001, SPEC-002, the profile reference, retrieval/security architecture, documentation map, and core README record the delivered contract.

## Public and failure contract

- `searchVault(root, { query, filters? }, options?)` accepts one explicit path or file URL and a non-empty Unicode-scalar query of at most 4,096 UTF-8 bytes.
- Matching is case-sensitive literal decoded-string matching over title then Markdown body only. Type, project, lifecycle status, workflow state, sensitivity, and tag filters are exact and ANDed.
- Search returns schema-valid manifest-allowed Bookie records in deterministic canonical-path order. Generic OKF is neither a hit nor a rejection. A schema-valid Evidence descriptor classifies its referenced Markdown file as resource data without opening resource bytes.
- Results carry `mode: "filesystem"`, `state: "working-tree"`, `commit: null`, a complete-source SHA-256 token, declared verification/freshness fields, sensitivity classification, and `untrusted: true`.
- Result count, title/excerpt bytes, aggregate returned title/excerpt text, manifest/concept bytes, traversal, concept count, YAML depth, diagnostics, and cancellation are bounded. `resultsTruncated`, `outputTruncated`, `complete`, and `diagnosticsTruncated` disclose distinct limits.
- `inspectConcept(root, { path } | { uid }, options?)` performs exact path or UID lookup only. Success returns one bounded exact UTF-8 source prefix while hashing the complete source. Duplicate schema-valid UIDs, invalid targets/selectors, missing targets, bounds, unsafe entries, or raced snapshots return no source text.
- Manifest-excluded sensitivity classes never participate in search hits, matched counts, or truncation decisions. Exact direct inspection may return one with `handling: "excluded"`; all output remains untrusted and callers must not log, index, checkpoint, or export it.
- Query never invokes Git, reads Evidence resource bytes, uses a network/provider/Pi/Redis boundary, exits the process, commits, or pushes.

## Red evidence

The first focused test failed because `searchVault()` and `inspectConcept()` were absent from the public package. Test-first implementation and adversarial critical review then exposed these failures before remediation:

- generic OKF beneath an Evidence root was incorrectly counted as a rejected concept;
- UID inspection reported ambiguity when one valid record and one schema-invalid candidate shared the selected UID;
- symlinks and multiply linked entries emitted diagnostics but allowed a false `complete: true` empty result;
- inspect rejected an uppercase `INDEX.md` record that search accepted even though only exact lowercase reserved basenames are reserved;
- case-variant `.git` path segments could enter search on a case-sensitive host;
- a malformed `/.md` selector was treated as a valid missing path;
- pre-aborted exact-inspect requests with malformed selectors could return normally instead of rejecting with `AbortError`.

Each regression passed after its focused repair. Additional probes covered Unicode paths and scalar-safe truncation, a late body match retained inside a bounded excerpt, every exact metadata filter, title/body precedence, excluded-content markers, malformed/generic Evidence descriptors, referenced Markdown resources, path/component limits, duplicate UIDs, invalid schemas, entry/concept/byte/diagnostic bounds, root and file-identity races, symlinks, hardlinks, cancellation during traversal, file URLs, declaration isolation, and forbidden process/network/provider imports.

## Acceptance demonstrated

- Exact Unicode title/body matching and every required exact metadata filter return deterministic canonical-path results.
- Results identify local filesystem/working-tree mode, decline to invent a commit, hash exact complete source bytes, and expose verification, freshness, sensitivity, and untrusted-data signals.
- Default, exact-boundary, plus-one, lower caller, aggregate output, result count, diagnostic, and cancellation tests make all limits observable without splitting Unicode scalars.
- Search continues beyond returned hits so complete `matchedCount` and `resultsTruncated` remain truthful.
- Generic OKF and valid Markdown Evidence resources do not become Bookie hits or false rejections; malformed candidates remain observable.
- Excluded sensitivity content, paths, UIDs, resource names, and markers do not enter search results or value-bearing diagnostics; exact inspect labels excluded handling restrictively.
- Traversal syntax, Git metadata variants, unsafe roots, symlinks, hardlinks, ambiguous UIDs, changed files/directories, and incomplete traversal fail closed; inspect returns no content from an incomplete snapshot.
- Core query invokes no Git, network service, Pi API, Redis client, process exit, commit, or push.

## Assumptions and follow-ups

- Filesystem search is the deterministic degraded/local read path and performs a linear safe scan. REQ-032's sub-500 ms warm target remains an indexed retrieval-service acceptance gate rather than a claim for a cold 50,000-file fallback scan.
- Query classifies Evidence resource paths from schema-valid descriptors but intentionally never opens resource bytes; exact resource validation remains `validateVault()`'s responsibility.
- Missing and undeclared sensitivity classes may participate only as labelled local data. [OQ-007](../open-questions.md#oq-007-sensitivity-fail-closed-boundary) remains open for later provider/index/export boundaries.
- Node exposes pathname operations rather than portable `openat`. Complete participating paths are identity-tracked and observed races fail closed; OS permissions or sandboxing remain necessary against hostile same-user ancestor renames between syscalls.
- [OQ-009](../open-questions.md#oq-009-pre-write-secret-detection-policy) still blocks CLI/Pi write exposure but does not constrain these read-only core APIs.
- The existing transitive `fast-uri` audit advisory remains separate maintenance work; BK-010 changed no dependencies and added no URI network sink.
- GitHub Actions passed while warning that `actions/checkout@v4` and `actions/setup-node@v4` target deprecated Node.js 20 and were forced onto Node 24; update those actions separately.
- BK-011 deterministic canonical JSONL export is the next ordered implementation item.

## Drift found and resolved

- BK-010's prior backlog sentence did not define its public API, exact matching semantics, source/trust fields, truncation, exclusion behavior, or failure contract. SPEC-001, SPEC-002, the profile reference, open-question boundary, retrieval/security architecture, and executable tests now agree on those details.
- The shared enumerator previously distinguished unsafe entries only through diagnostics. Query now observes that state explicitly so a false-empty scan cannot claim completion, without changing canonical validation authority.
- Case-sensitive reserved basenames and case-insensitive Git metadata segments are now consistent between search and inspect.
- No accepted ADR or product requirement was weakened or superseded.
