# BK-011 completion evidence

## Scope

Implemented deterministic canonical JSONL 1.0 export for one exact named local Git commit in `@bookie/core`. Core now resolves a sanitized ref once, validates and filters only the immutable commit snapshot, canonicalizes every included Bookie record, and streams complete bounded JSONL lines through a caller-owned asynchronous byte sink.

CLI publication, Pi tools, destination planning, destination adapters, and network execution remain later work.

## Files and behavior

- `docs/architecture/decisions/0006-exact-commit-streaming-export.md` records the exact-commit, versioned-record, preflight-before-sink, cancellation, and caller-owned publication boundary.
- `schemas/export/1.0/canonical-record.schema.json` defines the canonical record envelope and ties each top-level type to its complete matching profile schema.
- `packages/core/src/canonical-export-model.ts` defines the provider-free public request, sink, policy, record, success, and failure types.
- `packages/core/src/canonical-export.ts` validates and snapshots invocation inputs, applies limits, orders and recursively canonicalizes records, precomputes byte/hash receipts, drives sequential sink calls, and reports output uncertainty.
- `packages/core/src/vault-export-scan.ts` reads and completely validates one exact commit, classifies generic OKF and Evidence resources, enforces sensitivity policy, and produces normalized export records without reading worktree concept bytes.
- `packages/core/src/vault-git-base.ts` now exposes reusable exact-commit root/tree reading and bounded breadth traversal that prunes manifest-excluded subtrees while rejecting duplicate normalized paths and unsafe modes.
- `packages/core/src/vault-secret-detection.ts` implements deterministic local credential signatures. Detection defaults to `reject-detected`; the exact low-level `allow-unchecked` opt-out is an explicit own data property and is reported in every result.
- `packages/core/src/vault-markdown.ts` shares bounded CommonMark analysis between filesystem and commit-snapshot validation.
- `packages/core/test/canonical-export.test.mjs` covers deterministic success, every initial type, schema fidelity, exact bodies, Git provenance, sensitivity and secret policy, malformed trees, bounds, cancellation, sink uncertainty, and public declaration isolation.
- `packages/core/scripts/benchmark-canonical-export.mjs` reproduces included and mixed-sensitivity 50,000-concept exports.
- Requirements, SPEC-002, SPEC-005, security guidance, profile/retrieval documentation, package documentation, and the repository map now describe the implemented boundary.

## Public and failure contract

- `exportCanonicalJsonl(root, { sourceRef, write }, options?)` accepts one explicit vault path or file URL inside a local non-bare Git worktree.
- `sourceRef` follows the accepted canonical-ref or full SHA-1/SHA-256 object-ID grammar. It resolves once; later ref movement and all staged/worktree changes are irrelevant to emitted bytes.
- Every line validates against canonical record schema 1.0 and carries the resolved lowercase commit, exact source hash, profile, UID, canonical bundle-absolute `.md` path, type, title, complete decoded frontmatter, and exact decoded Markdown body.
- Records sort by exact UID. Object keys recursively use ECMAScript UTF-16 ordering, arrays retain order, accepted scalar/date/empty values retain semantics, and every record ends in one LF. Empty valid exports contain zero bytes.
- The result reports the selected secret policy, record and byte counts, and SHA-256 over exact concatenated JSONL bytes.
- The complete commit snapshot is validated before the first sink call, including manifest/profile policy, schemas, paths, UIDs, links, relations, Evidence modes/sizes/digests, sensitivity, and all configured limits.
- Manifest-excluded subtrees are pruned. Sensitivity-excluded records are validated but omitted before sorting, counting, hashing, or output. Missing/undeclared sensitivity or an included canonical field exposing an excluded UID/path fails with static redaction and zero sink calls.
- Deterministic high-confidence secret detection is enabled by default across included canonical string fields. A match returns `secret-policy` plus only static `EXPORT-SECRET` at `<redacted>`. `allow-unchecked` skips this heuristic only and never weakens sensitivity or validation policy.
- Invalid request/option types and above-default limits throw `TypeError`; cancellation rejects with `AbortError`, including while a sink promise is stalled.
- Invalid, incomplete, sensitivity-rejected, secret-rejected, and oversized snapshots invoke the sink zero times. A sink failure reports the attempted line conservatively through `possiblyWrittenRecords` and `possiblyWrittenBytes`. A caller must discard any prefix after failure or cancellation.
- Core invokes no network service, destination provider, Pi API, process exit, `git commit`, or `git push`.

## Red evidence

The initial focused test failed because `exportCanonicalJsonl()` and canonical record schema 1.0 did not exist. Test-first implementation and repeated adversarial review then exposed and repaired the following failures before merge:

- a working-tree query seam could not truthfully provide exact-commit provenance;
- malformed Git trees could emit duplicate normalized paths;
- deeply nested vault roots incorrectly charged repository-prefix entries against vault limits;
- recursive Git listing traversed and charged all descendants beneath excluded subtrees;
- a sink promise that never settled prevented cancellation from completing;
- an excluded UID could leak through an included record's generated canonical path;
- default credential detection missed qualified/camel-case/container keys, quoted/JSON/Markdown assignments, low-entropy values, nested credential structures, and long assignment or URI values;
- broad bracket placeholder recognition allowed arbitrary bracketed credentials to bypass detection;
- mutable request/options objects could replace the signal or sink after invocation and deadlock a stalled write;
- invalid `signal` values could become output failures or empty-export success instead of programmer `TypeError`.

Each regression was first reproduced through the public API or a malformed local Git fixture and then retained as automated coverage. Additional probes covered refs and full case-insensitive SHA-1/SHA-256 IDs, moving refs, worktree divergence, nested repositories, missing Git, disabled inherited Git selectors, gitlinks, symlinks, case-variant Git metadata, exact/one-over entry/resource/concept/output limits, invalid manifests and concepts, generic OKF, excluded resources and identities, Unicode key ordering, CRLF/no-final-newline bodies, placeholders, explicit unchecked export, abort timing, late sink rejection, and declaration/package boundaries.

## Acceptance demonstrated

- Repeating an export of one resolved commit and options produces byte-identical JSONL and the same exact output hash despite worktree edits or later ref movement.
- Every initial concept type emits a schema-valid line with complete decoded unknown metadata, exact source attribution, stable identity, and exact Markdown body.
- Recursive key ordering, record ordering, array order, Unicode, dates, null/empty values, framing, and SHA-256 receipts are deterministic.
- Full commit validation, source traversal, concepts, aggregate concept/resource bytes, diagnostics, output, and cancellation are bounded before publication.
- Excluded and unclassified records cannot contribute identifiers/content to bytes or value-bearing diagnostics; included controls still export.
- Default credential matches fail with static redaction and zero output; explicit unchecked mode is deliberate, cannot be inherited or selected by environment fallback, and is reported.
- Malformed trees, unsafe modes/paths, duplicate entries, invalid refs, Git selector injection, partial clones requiring fetch, sink rejection, stalled writes, races, and invalid invocation types fail closed.
- Empty, SHA-1, SHA-256, nested-vault, mixed-sensitivity, exact-boundary, one-over, and 50,000-concept scenarios pass.

## Assumptions and follow-ups

- Canonical JSONL requires local Git 2.29+ and a containing non-bare worktree. Filesystem search remains the no-Git degraded read path.
- The asynchronous sink is intentionally storage-neutral. File callers must stage privately, discard any uncertain prefix, and atomically publish only after success.
- Secret detection is deterministic and conservative rather than proof that content is secret-free. The low-level unchecked option exists for explicitly audited use; CLI/Pi exposure remains blocked until OQ-009 pins user-facing approval and pre-write policy.
- Canonical JSONL is release 0.1. Destination planning, receipts, adapters, network execution, and external-ID write-back remain release 0.3 work.
- OQ-005 remains open and does not alter the existing manifest/caller Evidence bounds enforced here.
- The transitive `fast-uri` advisory remains separate from BK-011 because this slice added no runtime dependency or network sink; [BK-023](../backlog.md) now tracks the patched upgrade as the next Ready maintenance item.
- GitHub Actions passed while warning that `actions/checkout@v4` and `actions/setup-node@v4` target deprecated Node.js 20 and were forced onto Node 24; update those actions separately.
- BK-023 is the next Ready maintenance item. BK-012 remains the next release-0.1 feature item but is blocked by the unresolved write-facing portion of OQ-009.

## Drift found and resolved

- REQ-016 and SPEC-005's `source_commit` field required exact commit bytes, while earlier CLI prose lacked a ref selector and filesystem query intentionally reported working-tree state. ADR-0006 and SPEC-002 now define a dedicated exact-commit export seam and future `--ref` CLI input.
- SPEC-005's earlier path example was extensionless while profile/core paths are bundle-absolute `.md` paths. Schema 1.0 now uses the canonical bundle-absolute form.
- Missing/undeclared sensitivity behavior was unresolved. OQ-007 now fails the complete export with static redaction and zero output.
- REQ-026 was refined with product approval so local credential detection is default-on while an exact audited low-level unchecked policy is optional; sensitivity exclusions remain non-bypassable. OQ-009 records that export-only decision without guessing the still-open write boundary.
- Canonical JSONL belongs to release 0.1; destination planning and adapters remain release 0.3.
- No accepted storage, canonical-integrity, append-only, provider, or degraded-read invariant was weakened.
